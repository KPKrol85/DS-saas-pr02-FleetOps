# Changelog

All significant changes to this project are documented in this file.

## [Unreleased]

### Changed

- Removed the unreachable duplicate public-page rendering architecture, leaving each public page with exactly one definition: its maintained static HTML document. `scripts/main.js` rewrites every public hash to its static URL and admits only `#/login`, `#/app` and `#/app/*` into the hash router, so the router cases for `/`, `/about`, `/contact`, `/product`, `/features`, `/pricing`, `/security`, `/careers`, `/privacy`, `/terms` and `/cookies` could never run. Deleted `scripts/ui/marketingPages.js` and its imports, `renderInfoPage` and the public route cases in `scripts/router.js`, and `renderLanding`, `renderLandingHeader`, `renderLandingFooter` and the renderer-only `getLandingThemeAsset` helper in `scripts/ui/layoutLanding.js`, together with the dead `.footer-links a` selector in `applyAriaCurrent` and the now-unused public entries in `routeLabels`. The reachable landing shell is unchanged — `initLandingShell`, `getLandingTheme`, `initResourcesMenu`, logo scroll, theme toggle, mobile navigation, focus trapping and the header scroll state — as are the public URLs, the hash application routes and the `#/app` authentication guard. The Vite production JavaScript bundle drops from 201.30 kB (46.97 kB gzip) to 104.65 kB (27.70 kB gzip).
- Migrated the project to Vite as the single development, module, build and production-preview tool. `vite.config.js` declares every maintained HTML document as a build entry, so the multi-page public structure, the hash-routed demo application and all production URLs are unchanged; development runs on `127.0.0.1:8181` and the production preview of `dist/` on `127.0.0.1:8182`, both with strict port handling. Active runtime JavaScript moved from 25 ordered `<script defer>` tags to a Vite-managed ES module graph behind a single `/scripts/main.js` module entry, with explicit imports replacing the implicit load order (the `window.*` namespaces remain as the project's internal contract). Production-static files moved to `public/` (`assets/`, `sw.js`, `_headers`, `_redirects`, `robots.txt`, `sitemap.xml`) so Vite copies them to `dist/` verbatim under their existing paths, while `assets/img-src/` stays an out-of-build source input and `optimize-images.js` now writes to `public/assets/img/`. Retired `build-dist.js`, `postcss.config.js` and the `cssnano`, `postcss`, `postcss-cli` and `terser` dependencies, together with the Python `http.server` preview workflow; CSS and JavaScript bundling and minification are now owned by Vite. Reworked the npm contract to `dev`, `build`, `preview` (`preview:dist` kept as an alias) and turned `npm test` from a build alias into `qa:css-vars` plus the smoke suite, so no normal command regenerates image assets. The service worker keeps its `/sw.js` production registration and is skipped during development, and Playwright now runs the existing smoke suite against the built production preview.

### Fixed

- Fixed the public pages presenting fabricated customer endorsements and unqualified performance figures. The landing page carried three testimonial cards — `figure`/`blockquote`/`figcaption` markup under the heading "Operatorzy o FleetOps" — attributing quotations to `COO, CargoNord`, `Lider operacji, FreshLine` and `Fleet Manager, AeroParts`, none of which the project can support. The section is now "Scenariusze demo" / "Co pokazuje demo FleetOps": the same three ideas (mniej ręcznego sprawdzania statusów, sprawniejsza komunikacja operacyjna, jedno miejsce do kontroli floty) are stated as illustrative operational scenarios in `article.card--scenario` elements with plain `.card__text` copy, the quotation and attribution markup is gone, and the lead states that these are przykładowe scenariusze operacyjne and not opinie klientów ani opisy wdrożeń. No replacement company names, roles or anonymous customers were introduced. On the product page the panel labelled "Wskazniki zaufania" became "Przykładowe wskaźniki demo" and now carries a visible note directly beneath the figures: "Powyższe wartości są ilustracyjne i służą wyłącznie prezentacji interfejsu. Nie są to zmierzone wyniki działania FleetOps, rezultaty klientów ani zobowiązanie SLA." The `96.8%`, `99.6%` and `12 min` cards are unchanged and retained only as demo data. In CSS, `.grid--testimonials` became `.grid--scenarios`, `.card--testimonial` became `.card--scenario` with `grid-template-rows: auto 1fr` for the two-element card, the now-unused `.card__quote`, `.card__author`, `.card__author-role` and `.card__author-company` rules were removed, and `.marketing-hero__stats-note` was added from existing tokens. The company names remain in `scripts/data/seed.js` as in-application demo order data, which is not a public marketing claim.
- Fixed the public contact form confirming a delivery and a reply that no code path can produce. `#contactForm` has no `action`, no Netlify integration and no network call anywhere — `bindStaticContactForm` prevents the native submit, validates locally and never transmits the values — yet the page promised a reply "w ciągu 1 dnia roboczego", the FAQ repeated that commitment, the consent checkbox asked for agreement to real contact, the action read "Wyślij zapytanie" and the confirmation was a success toast reading "Dziękujemy! Wkrótce się odezwiemy." The form now carries a visible pre-submit disclosure stating that it is demonstrational, that the entered data is not sent, stored as a contact request or received by anyone, and that real contact goes through `kontakt@kp-code.pl` or `+48 533 537 091`. The checkbox became an acknowledgement of that demo behaviour, the action reads "Sprawdź formularz demo", and the confirmation is a neutral-tone toast: "Formularz demonstracyjny - dane nie zostały wysłane. Kontakt: kontakt@kp-code.pl lub +48 533 537 091." The automatic `form.reset()` was removed so the typed values stay available to copy into a real message. The one-working-day commitment is gone from the form lead and the FAQ with no replacement response time, and the page hero, the contact-panel note and the form-referencing FAQ answers now direct genuine enquiries to e-mail and telephone. The privacy policy was reconciled with the same truth: section 4 describes the form as a demonstrational interface element whose values stay in the browser and reach no backend, mail service or other recipient, and section 3 no longer lists form input among the processed data. Form validation, labels, required states and the published `mailto:`/`tel:` contact surfaces are unchanged.
- Fixed the settings demo reset destroying local demo data from a single unconfirmed click. "Resetuj" now opens the project's existing confirmation modal — the same component and confirm/cancel body used by the orders, fleet and drivers delete confirmations — titled "Potwierdzenie resetu demo", and `FleetStore.resetDemo()` runs only from its "Resetuj dane demo" action. The confirmation names the full reset scope (zlecenia, pojazdy i kierowcy including records added in the demo, historia aktywności, filtry oraz preferencje list i tabel, motyw i tryb kompaktowy, zakres raportów) and states that the current session and the selected role stay unchanged. Cancelling, Escape and backdrop dismissal leave every record and preference untouched, show no success toast and do not redirect. The reset card description changed from "Przywraca dane demo do stanu początkowego" to "Przywraca dane demo i preferencje interfejsu do stanu początkowego". The post-confirmation behaviour — control synchronization, the success toast and the redirect to `#/app` — is unchanged, as is `FleetStore.resetDemo()` itself.
- Fixed the application top bar presenting two enabled controls that did nothing. The search input and the "Alerty" button in `scripts/ui/layoutApp.js` had no handler anywhere in the project — global search and an alerts panel are not FleetOps features. Both controls remain in the top bar but are now natively `disabled` with an explanatory title, the treatment already used for the orders CSV export: "Wyszukiwanie globalne jest niedostępne w wersji demo" and "Alerty są niedostępne w wersji demo". The button's `aria-label` changed from "Otwórz alerty" to "Alerty" so its accessible name no longer promises to open a panel. A local `.search input:disabled` rule supplies the affordance the bare input did not inherit from `.input:disabled`. The per-view search inputs in orders, fleet and drivers, the role switcher, the theme toggles and the user menu are unchanged.
- Fixed offline mutations being presented as queued work that was silently discarded on reconnect. `ensureOnline` in `scripts/state/store.js` previously stored only an action label and timestamp in an offline queue with the message "Tryb offline - akcja dodana do kolejki", then `setOnlineStatus` cleared that queue on reconnect behind a "Połączenie przywrócone" success toast, so the create, edit or delete was never applied and the user was never told it had been lost. Offline mutations are now rejected outright: the record is not created, edited or deleted, and the user sees "Tryb offline - zmiana nie została zapisana. Powtórz akcję po przywróceniu połączenia." Reconnect still announces "Połączenie przywrócone" but no longer implies a completed sync. The now-unreachable queue state, `enqueueOfflineAction`, `clearOfflineQueue` and the `fleet-offline-queue` storage key were removed, with the legacy key purged from `localStorage` for existing sessions.
- Fixed the demo application losing its navigation at a viewport width of exactly 1024 px. The application shell mixed two breakpoint boundaries: the mobile top bar hosting `#drawerToggle` was withdrawn and the two-column `.app-shell` grid activated at `min-width: 1024px`, while the sidebar only became a static grid item at `min-width: 1025px`. At exactly 1024 px the shell therefore exposed no navigation affordance and, with the sidebar still out of flow, rendered `.app-main` into the 240 px sidebar column. The application-shell rules — the shell grid, the `.app-main` top padding that clears the fixed mobile top bar, the withdrawal of `.app-topbar` and the backdrop, and the sticky route topbar with its theme toggle — now all switch at `min-width: 1025px`, the boundary the sidebar, the public-site drawer and the viewport-conditional drawer semantics already used. The drawer shell stays valid through 1024 px, desktop mode starts at 1025 px, and no widths, spacing, markup or public-site breakpoints changed.
- Fixed the public site's `#mobileNav` and the application's `#appDrawer` announcing themselves as a modal dialog and being hidden from the accessibility tree at desktop widths. Both containers now derive `role="dialog"`, `aria-modal` and `aria-hidden` from a `matchMedia` check against the same breakpoint their own CSS uses to switch into persistent navigation (`min-width: 1025px`), applying the overlay attributes only while genuinely acting as an overlay and removing them once the container is desktop-persistent. State stays correct through route re-renders (`renderAppShell` no longer reintroduces a hardcoded `aria-hidden="true"`) and through live resizes between mobile and desktop without a page reload, with the `matchMedia` listener cleaned up per render so it cannot accumulate. Existing open/close, focus trap, focus return, Escape and backdrop behaviour is unchanged.
- Fixed collapsed accordion panels (`scripts/ui/components/accordion.js`) remaining exposed to assistive technology while visually clipped via `max-height: 0`. Collapsed panels now also carry the `hidden` attribute, applied immediately on initial render and, for user-triggered collapses, only after the existing `max-height` transition finishes so the closing animation is unaffected; opening a panel removes `hidden` before the transition starts. `aria-expanded` synchronization and the open/close animation are unchanged.
- Fixed the settings toggle track and settings checkbox rendering without their intended fill. Both controls referenced an undefined `--surface-muted` custom property, so the `background` declaration was invalid at computed-value time and the controls fell back to a transparent background in both themes. They now use the existing `--surface-2` token — the design system's recessed surface inside a `--surface` card, already defined for the light and dark themes — rather than introducing a redundant alias. This also restores `npm run qa:css-vars` to a passing gate.

### Added

- Added the standalone FleetOps static frontend implementation, covering public marketing and legal pages (`product`, `features`, `pricing`, `about`, `contact`, `security`, `careers`, `privacy`, `terms`, `cookies`, `404.html`) and a hash-routed demo application under `#/app`, `#/app/orders`, `#/app/fleet`, `#/app/drivers`, `#/app/reports` and `#/app/settings`.
- Added a hash router with an authentication guard for demo routes, `aria-current` synchronization and scroll reset on navigation.
- Added local demo record management for orders, fleet and drivers, including create, edit, delete, filtering, sorting, load-more pagination and a record details drawer.
- Added browser-local demo state persistence in `localStorage` using versioned storage keys (`fleet-domain-v1`, `fleet-activity-v1`, `fleet-list-prefs-v1`) and a demo data reset action.
- Added a local demo role model with administrator, dispatcher and driver roles enforced through action-level permission checks in `scripts/core/permissions.js`.
- Added interface settings for light and dark theme, compact mode, dashboard range and list preferences.
- Added JSON export for reports; CSV export of orders is intentionally disabled in the demo.
- Added shared UI components for dropdowns, modals, toasts, accordions, tables and the record drawer.
- Added a service worker (`sw.js`) that precaches the app shell and public routes and removes outdated `fleetops-` caches on activation.
- Added a Web App Manifest with application icons, screenshots and shortcut entries.
- Added a production build pipeline (`build-dist.js`) that emits a `dist/` output with CSS minified through PostCSS and `cssnano` and JavaScript minified through `terser`, and copies `sw.js`, `_headers`, `_redirects`, `robots.txt` and `sitemap.xml`.
- Added an image generation pipeline (`optimize-images.js`) producing AVIF, WebP and JPG variants from source images with `sharp`.
- Added static-hosting deployment configuration: security and cache headers in `_headers`, asset passthrough, trailing-slash redirects and index fallback in `_redirects`, plus `robots.txt` and `sitemap.xml`.
- Added a repository-wide line-ending policy in `.gitattributes` — LF for text sources and documentation, CRLF for Windows batch files, and explicit `binary` marking for image and font assets — and normalized the affected sources once, so checkouts are byte-identical across platforms and diffs no longer carry whole-file line-ending churn.
- Added a root `.gitignore` excluding dependencies (`node_modules/`), generated build output (`dist/`), Playwright artifacts (`test-results/`, `playwright-report/`), local Netlify state, runtime logs and operating-system metadata, and untracked the previously committed Playwright run artifact `test-results/.last-run.json` (kept on disk, now ignored), so generated output can no longer be committed by accident and the README statement that the repository holds no recorded test-run results is true.
